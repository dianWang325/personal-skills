# experiment-record 使用说明书

把实验日志和已知环境交给 Codex，生成可追溯的实验记录，后续可以查找做过的实验、比较结果并进行阶段复盘。支持成功、失败、中断和只完成部分步骤的实验。

## 安装

需要 Python 3，归档脚本仅使用标准库，无需安装 torch 或访问 NPU。

将本目录完整复制到 `$CODEX_HOME/skills/experiment-record`；未设置 `CODEX_HOME` 时使用 `~/.codex/skills/experiment-record`。在新会话中使用 `$experiment-record` 调用。

默认实验仓库为 `D:\experiment`，也可以在请求中指定其他路径。使用其他路径时，调用脚本同样传入 `--root`。安装 skill 本身不会自动创建实验记录或 Git 仓库；首次使用新目录时可以让 Codex 初始化目录、说明文件和空索引，需要 Git 管理时明确要求初始化 Git。

## 第一次记录实验

把运行日志作为附件、可访问的本地文件路径或聊天文本提供给 Codex，再发送：

```text
用 $experiment-record 把这次实验记录到 D:\experiment。
日志在：<本地日志路径>，另附部署和压测命令。
执行时间：<日期和大约时间>，时区：<已知时区>。
模型：<模型名称或路径>。
机器/环境：<机器别名、NPU 型号和卡数、镜像、已知软件版本>。
实验目的：<可选>。
遇到的问题：<可选>。
日志中没有的信息标为未知。
```

尖括号内容由你填写；不需要每项都提供。Codex 会从已有日志提取可确认的信息，缺失项列入待补信息，不会用当前环境推测过去的版本，也不会把归档时间当作执行时间。

建议同时提供服务端日志、部署命令、压测命令和压测汇总。日志只能证明启动完成时，记录会注明尚无完成压测的证据。

## 一条记录包含什么

| 内容 | 记录范围 |
|---|---|
| 执行时间 | 开始/结束时间精确到分钟，独立标注时区与时间依据 |
| 模型 | 名称、路径、revision、dtype、量化方式 |
| 机器 | 机器别名、NPU 型号/卡数、操作系统、驱动/固件等已知信息 |
| 环境 | 镜像 tag/digest，vLLM、vLLM-Ascend、Triton、CANN、torch、torch_npu、Python，以及使用的 AISBench 和 aisbench_auto_tools_prefix 的独立版本或 commit |
| 部署 | 实际命令、环境变量、拓扑、TP/DP/PP/EP、图模式、上下文长度、调度和 KV cache 等核心参数 |
| 特性实际状态 | 请求配置、日志证明的生效/禁用/回退/混合/未知状态、触发条件、回退路径、事件顺序、影响范围与关联测量轮次 |
| 压测 | 工具、命令、数据集、输入/输出长度、请求数、并发/QPS、预热、每轮指标及失败请求 |
| 精度评测 | 数据集/版本/split、prompt/few-shot、生成与评分配置、各子任务分数、样本计数和失败样本证据 |
| 测试 | 框架/版本、执行命令、选择的用例/参数矩阵、判定标准、逐用例结果、状态计数、退出码和失败详情 |
| 结果 | 结果摘要、证据支持的结论、适用范围与限制 |
| 可选内容 | 实验目的、踩坑现象、处理过程、验证结果 |
| 可追溯信息 | 日志来源、关键片段或行号、附件路径/哈希、缺失项、关联实验、标签 |
| 修订与排查 | 修订前后结论、原因和证据；每次成功/失败/无效尝试、排除项与未决问题 |
| 经验与反馈 | 有适用条件和反例的经验，后续复用时的有效/失效/受限/未决反馈，绑定经验内容版本 |

完整字段约定见 [record-format.md](references/record-format.md)。版本未知时留空；没有压测结果时不填零。根因猜测与已验证结论分开保存。

### 配置开启与实际生效分别记录

例如请求开启 CPP，但运行日志显示不满足条件并发生回退，记录会同时保留“请求开启”与“实际回退”，保存原文原因、回退路径、发生阶段、rank/请求范围及对应的压测/精度/测试轮次。运行中多次回退或恢复会逐项保留，不只写最终状态。索引也会展示特性实际状态，详情见 [特性记录约定](references/runtime-features.md)。

只有启动参数或初始化日志、缺少实际执行证据时，实际状态标为 unknown；没有回退警告也不代表已证明全程生效。单个 rank 或请求发生回退，不会直接认定所有请求都回退。混合路径结果会注明限制，复盘不会直接将它作为特性全程开启的性能收益。

### 提供的脚本一起保存

提供服务拉起脚本或压测脚本时，Codex 必须原样保存实际文件内容，不只记录执行命令。精度评测/测试脚本、已有的依赖配置和环境文件同样保存。脚本放在该实验的 evidence/ 下，例如 `evidence/start_service.sh`、`evidence/benchmark.sh`，无需增加目录层级。

每份快照记录来源路径/消息、归档副本 SHA256、是否改写的说明，并通过 script_refs 关联部署或测量轮次。多轮脚本不同、同名不同内容时分别留存，不覆盖旧快照。会记录是否有证据证明它是运行当时使用的版本；当前提供的文件不自动视为历史执行版本。只有片段或依赖不全时明确注明，不能保证完整复现。保存脚本不会执行脚本。

### 涉及验证时必须保存明细

压测、精度评测和测试都必须保留实际命令、输入/配置、详细结果和报告证据，不能只留“通过”、总分或单个吞吐数字。多轮测量、各数据集/子任务、各用例的已有结果都保留，包括失败轮次；大型逐用例结果可以通过原始报告保存。具体字段见 [验证明细约定](references/validation-details.md)。

将可获得的原始配置、汇总报告和日志保存到实验 `evidence/`，记录路径与 SHA256。大体积逐请求/逐样本输出可外部引用，但本次实验的详细汇总结果要落在实验目录。只有部分材料时照常归档，列出缺失项，并将 `details_status` 标为 `partial`；运行是否通过和记录是否完整分别表示。不会为了补齐材料自动重跑。

使用 AISBench 或 `aisbench_auto_tools_prefix` 时，也请提供当时实际使用的各自版本号/commit、dirty 状态、工具路径和评测所在机器/容器等已知信息。它们分别保存为 `environment.versions.aisbench` 与 `environment.versions.aisbench_auto_tools_prefix`，不以服务端版本替代客户端版本。没有版本元数据的脚本可用内容 SHA256 标识；仅有目录名不足以确认版本。缺失信息会单列，不会猜测，多轮版本变化也会分别记录。

### 完整压测日志与逐轮配置对应

原始压测日志必须全文保存在实验 evidence/，保留原始输出、换行及已有格式，便于以后打开截图；摘要、截取的尾部、截图和远端路径都不能替代完整日志。stdout/stderr 分离或存在轮转分片时分别保留。仅有部分日志或远端文件仍在写入时，会标 partial/unknown 并说明缺失，不能称为完整归档。

每轮压测以稳定 run_id 绑定服务实例、service_config_refs（实际服务配置）、benchmark_config_refs（本轮负载配置）、log_refs（完整原始日志）和 log_completeness。摘要自动生成“服务配置 → 压测配置 → 压测日志”文件链接表，按轮次直接打开，不靠文件名猜对应关系。共用日志需要标清各轮范围。详见 [压测日志与配置追溯](references/benchmark-traceability.md)。

## 文件在哪里

```text
D:\experiment\
├── README.md
├── AGENTS.md
├── INDEX.md                         实验总索引
├── YYYYMMDDHHMM_模型名\
│   ├── record.json                  结构化事实来源
│   ├── README.md                    从 JSON 生成的实验摘要
│   └── evidence\                   原始日志或原文摘录
└── reviews\
    └── YYYY-MM-DD-主题.md           按需生成的复盘
```

实验目录直接放在仓库根目录，例如 `202610172030_Qwen3-32B/`，不按年月建立额外层级。时间取实验开始时间，模型名取名称或路径的最后一段，也可用 `--model-name` 指定简短名称。非法路径字符替换为短横线、空白替换为短横线，模型名最多保留 80 字符；原始模型标识完整保存在 JSON 中。

时间未知的实验 ID 使用 `undated_归档时间_模型名`；索引仍显示执行时间未知。模型未知使用 `unknown-model`。补齐信息后保持 ID 和目录稳定。

同一配置的多轮测量可以归为一条记录；模型、代码、拓扑或关键配置变化时拆分并关联。同一分钟同模型发生重名时追加 `_02`、`_03` 等序号，避免覆盖，但语义去重由 Codex 阅读日志和既有记录完成，脚本不会自动判断两份日志是否来自同一次运行。

## 补充、检索与复盘

现有 record.json 新增 attempts、lessons、reuse_feedback、retrieval、revision_history 五组字段；摘要和索引一起展示，不新建更深的实验/知识目录。旧记录继续可读，不补造历史。

补充已有记录：

```text
用 $experiment-record 补充实验 <实验 ID>：
这是当时的镜像 digest 和 vllm-ascend commit，请更新已有记录，保留证据来源。
```

Codex 会用 update 保存修订原因及前后内容，不抹去旧判断。失败/无效的排查同样保留；已有排查、经验和反馈条目只追加，更正时用 supersedes 指向旧条目。经验需要适用模型、版本、硬件、配置/负载、特性实际状态等条件，未知条件不代表通用。复用反馈指向确切经验内容哈希，避免后来改写结论后旧反馈错配。

检索历史：

```text
用 $experiment-record 找出 Qwen 在 TP8 配置下做过的实验，列出环境、吞吐、TTFT 和记录链接。
```

也可以说“查找 CPP 回退的实验，列出失败尝试及后续纠正”。search 按当前 JSON 做忽略大小写的多词 AND 检索，支持模型、标签、状态、特性和日期筛选，返回命中字段与片段；不扫描原始日志、不做语义搜索。--include-history 可查被修订的旧内容。命中材料后仍需核对状态、适用条件和原始证据。

阶段复盘：

```text
用 $experiment-record 复盘 2026-10-01 到 2026-10-31 的实验。
按模型分组，比较条件一致的实验，整理结果、反复遇到的问题、证据不足的结论和下一步建议。
把复盘保存到 D:\experiment\reviews。
```

复盘会链接原始记录。模型、硬件、版本、输入/输出长度、负载、精度、预热或指标口径不同，都会影响可比性；单次测量不会被描述为已证明的稳定提升。执行时间未知的实验无法可靠归入时间区间，会单独提示。

复盘还会汇总哪些旧结论被纠正、哪些失败路线已排除、哪些经验被再次支持或在其他条件下失效。详见 [修订、排查与复用约定](references/experience-and-history.md)。

不会自动设置定期任务。希望每周或每月复盘时，另行明确要求创建自动化。

## 手动使用归档脚本

通常让 Codex 操作即可。以下是 Windows 默认安装路径示例；其他安装位置替换脚本路径。PowerShell 中运行：

```powershell
$recordScript = "$env:USERPROFILE\.codex\skills\experiment-record\scripts\records.py"

# 生成 JSON 骨架；输出文件必须尚不存在。
python $recordScript template --output 'D:\experiment\draft.json'

# 填写 draft.json 后归档；title 必填，其他字段遵循骨架类型。
python $recordScript --root 'D:\experiment' add --input 'D:\experiment\draft.json'

# 从当前 record.json 复制一份到临时文件，填写修改后，保留原 revision_history。
python $recordScript --root 'D:\experiment' update --record '<实验ID>' --input '<修改后的完整JSON>' --reason '补充证据或修正原因'

# 仅重建阅读视图（不能替代 update 保存修订历史）。
python $recordScript --root 'D:\experiment' rebuild

# 按执行开始日期筛选，包含首尾两日；同时返回时间未知的记录。
python $recordScript --root 'D:\experiment' list --from 2026-10-01 --to 2026-10-31

# 按问题检索，支持 --model、--tag、--status、--feature 和日期过滤。
python $recordScript --root 'D:\experiment' search --query 'CPP 回退'

# 只读核验附件存在性、SHA256、配置/脚本/日志引用、历史及反馈归属。
python $recordScript --root 'D:\experiment' verify

# 为复用反馈获取来源经验的准确内容哈希。
python $recordScript --root 'D:\experiment' lesson-digest --record '<来源实验ID>' --lesson '<经验ID>'
```

`add` 归档填好的 JSON 并生成摘要和索引；日志解读、证据复制、语义去重以及复盘由 Codex 完成。脚本不会自动解析原始日志或采集环境。草稿不属于实验记录，归档完成后可自行移走。

`record.json` 是事实来源。不要直接修改生成的实验 `README.md` 或 `INDEX.md`，否则 `rebuild` 会覆盖这些修改；补充说明应写入对应 JSON 字段。

verify 退出码：0=passed，1=failed，2=incomplete（如外部附件未校验、缺哈希、缺配置—日志对应关系或未确认完整日志）。校验只证明本地档案结构和材料的一致性，不证明实验成功或经验结论正确；不会改写文件或自动重置哈希。补充/修正记录请使用 update。

## 自动读取远端文件

归档时允许自动读取与本次实验相关的远端脚本、日志、报告、配置和直接依赖，并只读查询工具版本，无需逐文件确认。机器/容器端点可以来自你的说明或已有上下文；无法确认归属时再询问。不会执行这些脚本、修改远端环境或自动重跑实验。

文件默认原样保存，不主动脱敏；登记来源机器/容器/路径、采集时间、归档路径和 SHA256。下载后校验哈希，无法独立校验远端哈希时会注明。远端当前内容不自动视为历史运行版本，仍需日志或 manifest 支持。

## 日志与数据保存

日志默认保留原样副本或注明来源的原文摘录，不主动脱敏。压测原始日志必须全文本地保存；其他大文件可以只记录外部路径和 SHA256，此时文件尚未复制到实验仓库，仍需单独保存或备份。明确的认证凭据如确有必要保留，只放本地不受 Git 跟踪的原始附件，摘要和结构化记录不复制凭据值。

个人 skills GitHub 仓库保存可复用 skill 代码和本说明书；本地实验仓库保存真实实验数据。归档允许自动只读访问相关远端文件和查询版本证据；不会自动 Git 提交、推送或执行实验。
